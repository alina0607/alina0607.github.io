Overview

Sell Anything is a game built end-to-end from scratch. The player draws something with the mouse, a classifier recognises it, and three to five AI buyers, each with their own traits and budget, take turns asking about the item. Every answer moves every buyer's offer: a big dog is a plus for the hiker and a deal-breaker for the buyer in a small apartment. The player sells to the best offer, or keeps it.

Architecture

Two processes talk over newline-delimited JSON on localhost: a C++ game, and a Python ML service that holds the sketch classifier, the price engine and the buyer model.

C++ game Python ML service engine: loop, scenes, text, NDJSON sketch: rasterize strokes like Quick, Draw!, OpenGL / DGL / null <------> CNN (345 classes) game: canvas, confirm, buyers: item schemas, price engine, host round UI llm: tokenizer, GPT, pre-training, SFT

The Buyer Model — a GPT Trained from Scratch

A 12.9M-parameter Llama-style transformer (RMSNorm, RoPE, SwiGLU, grouped-query attention, KV cache) with its own SentencePiece tokenizer (8k vocabulary), pre-trained on FineWeb-Edu and fine-tuned on 112k dialogue examples generated by the price engine. It writes what the buyers say and judges how each answer moves their interest.

The price engine owns every number. A model line that disagrees with the engine's judgement, or garbles the question, falls back to a phrase pool, so the game never shows a contradiction.

Every version was scored on the same questions, including 33 items it never saw in training:

About 700 questions per column (±2–4 points); "used in play" is 30 autoplayed rounds. The v1–v2 play figures were measured before a guardrail fix that made short questions stricter.

What the table shows: each step fixed a measured failure rather than adding capacity. The model kept copying rare item names wrongly, so v4 stops asking it to spell them at all: it writes a placeholder and the engine fills in the name.

Sketch Classifier

A VGG-style CNN over all 345 Quick, Draw! categories (71.7% top-1, 87.1% top-3 on held-out drawings). Player strokes are rasterised exactly the way the dataset made its bitmaps, with a pixel correlation of 0.996 against the official images. Details on the Sketch Recognition page.

Engine

  • Rendering backend chosen at run time: batched OpenGL, DigiPen's DGL, or a headless backend for tests
  • Bitmap-font text, textures, sprite sheets and animation on every backend
  • A compatibility layer runs DGL programs on macOS and Linux, so the DGL backend is built and tested off Windows too

Engineering

One command runs every check, cheapest first: lint, Python tests, the C++ build, engine tests, an end-to-end round (the real game, headless, against the real server), data freshness, a model regression check, and a static-analysis gate on new findings.
